# 13. External Skills Layer

Payloads, dependencies, staging, realtime providers and Telegram. Discovery, review, grants, dependency readiness and enablement remain separate because collapsing any two turns a UI toggle into execution authority. Context snapshots: §6; protocol: `CREATING_SKILLS.md`.

### Skill gates

Discovery confers no trust; a review PASS installs no dependencies; `enabled=true` does not prove readiness. Payload/state roots: §1. Install → preflight → digest-bound review or acceptance → grants → dependencies → enablement → execution; extensions also need registration (§10.8). Enabled peers' conflicts apply symmetrically, without deletion. `skill_lifecycle_queue.py` deduplicates mutations; panels lend its lane and persist only for installed bytes. Full reviews stay private; UI labels dead/stale jobs interrupted without writes. List reads heal nothing. Lifecycle-locked ordinals are allocated after job start, so retry history stays explainable without a UI counter becoming review authority.

Each execution resolves the canonical directory through the full loader. Conflict readers use fresh manifest/enablement peers (`skill_peer_inventory.py`), not payload hashes or partial executables. Both use `skill_loader._native_platform_visible`: foreign built-ins stay hidden except re-seeded Unix remote on Windows (§2); its provenance survives OFF for later intentional ON, not execution authority. `skill_conflicts.py` supplies their shared duck-typed verdict. Both refresh after slow lifecycle work: cross-process disable/revoke/restored-mtime edits apply next request; valid manifests retain conflicts despite unreadable payloads.

### Skill review authority

Reviewer rights govern checks in a private copy, not activation; Full is not an OS sandbox.

Preflight failure stays PENDING, never advisory-overridable BLOCKERS. Records bind the release digest (`skill_identity.py`: payload and dependency declarations, no install notes); conversion rebinds only unchanged bytes. Host acceptance admits exact bytes through trusted source, Cyber-only `self_check`, owner Skip or selected-task owner edit. Ordinary owner-requested edits use `skill_owner_action` Skip with their `owner_source`; edits stale prior acceptance. Review-source blockers stay off even after Advisory author finish. Elsewhere an author may accept substantive feedback or an exact terminal job/hash reference with partial feedback or disclosed unavailability, running preflight and recording `author_disposition.review_reference`. A live silent critic is not unavailable. `SkillReviewState.gate_for` owns admission without rewriting critics: Blocking needs fresh approval; Cyber keeps P0/P3 judgment. Publication: §6.

### Telegram built-in

Thoughts and completion notices read bounded chat/progress from `state/dialog.sqlite`; legacy log paths are addresses only. Unavailable windows (import, failed segment, invalid interval) never initialize or advance notification seen IDs; thoughts retain preview limits.

`skills/telegram/` owns the in-process bridge and supervised companion (sidecar, tunnel/menu rollback, heartbeat, singleton). Text needs no tunnel. The built-in needs grants; Colab waits for executable installation, auto-grants eligible missing items under the owner's choice, then enables. `data/state/skills/telegram/` holds binding, companion, rollback, cursors, tunnel cache and bounded derived message references; map-write faults warn without stopping delivery. Confined files enter `/chat/inject` → `data/uploads`; quiz answers, `/chat/decision`. Other replies carry row/work facts, never routing; status notices reference work, not unseen Main answers. Earlier same-chat owner messages get native replies; Continue stays separate; relays are silent on success, one line on failure. Oversized files point in-app or to an active Mini App, never starting a tunnel or publishing a URL. `lib/telegram_i18n.py` uses `OUROBOROS_UI_LANGUAGE` (§7), preserving host text; `/language` uses Host `/ui/language`. The completion toggle gates terminal/Main notices; Off consumes IDs. Replay enriches `completion_notice` (§3), not text. Silent Mode, replies/files/quizzes and salvage stay independent. Events only wake `TypingCue` over `gateway/reply_preparation.py` (DESIGN §9). `TELEGRAM_PROXY` covers Telegram API only; other egress is direct. Dependency: locked `httpx[socks]`; limits/proxy forms: `skills/telegram/SKILL.md`.

`skill_catalogue.py` pages whole compact `list_skills` records, disabled/unreviewed/broken/colliding included, with omission counts. Snapshots track membership, not atomic pages. Named reads return full diagnostics and `manifest.read` for the loader-selected `SKILL.md`/`skill.json`, whose bodies remain there. Unreadable payloads do not hide readable manifests; unparsed/colliding manifests have no address. Unknown names return `found: false`; oversized details use the generic result source. `model_experience` reaches bounded context; `SkillManifestError` carries `fix_hint`. Delegate index: §6.

### Sources, installs and dependencies

`skill_sources.py` owns the list: until chosen, Official trusted and Community review; trust changes affect future installs. Git caches (`state/skill_sources/`) first read github.com HTTPS without the configured GitHub token, retrying only authentication refusals once with that token. Other URLs use host credentials. Hubs provide entries/digest endorsements/categories; plain repositories provide manifest folders. `skill_source_install.py` verifies releases and records basis. `check: review` buys the panel; Cyber-only `self` records why exact read bytes may run; trusted sources skip review. HTTP contract: `gateway/skill_source_contracts.py`.

Updates compare candidate and optional local digests. Replace keeps `.previous`; keep skips; merge uses the owner's task door. Review-basis updates retain payload/lifecycle state and name `pending_update`. Completion, owner Skip and startup settle in the lane: accept executable bytes or restore/reconcile, recording `update_rejected` for review, preflight, landing or dependency failure. Startup leaves live reviews alone. Pre-update records restore interrupted landings; superseded installs discard snapshots. Partial restores retain evidence and never replace twice. No-review updates bind `owner_skip` to exact bytes. Starters accept any source: absent/blank means defaults, `[]` none; `OUROBOROS_STARTER_SKILLS_TURN_ON` defaults true (§7). Built-ins precede Git fetches.

ClawHub lands archives atomically with per-file hashes. Accepted dependency declarations authorize literal build/check argv (`marketplace/install_specs.py`); manual instructions remain guidance. `state/skills/<name>/dependency_cache` holds caches, `deps.json` results; absent checks stay unknown, drift stales readiness. `provenance.py` clears only the local receipt. Script runtimes: `tools/skill_exec.py`, `CREATING_SKILLS.md`.

### Extension import and isolation

`_stage_extension_import_tree` (`extension_import_staging.py`) shares complete `__extension_imports/` trees by content hash and runtime/dependency identity, reference-counted per process; reclamation needs no references and dead owners. Review/grants bind to code. Per-call children reuse that loader with scrubbed env and proxy tools/routes/WS/UI/settings/companion descriptors; persistent subscriptions and supervised tasks need in-process or companion lifecycle. The capability matrix, not platform names, describes support. `extension_catalog.json` caches success only for exhaustive `catalog_inputs`: its key hashes runtime, host revision, grants and declared settings/env values, never persists values. Other registration dependencies keep the catalog child; bundled payloads never opt in implicitly (`declared_catalog_inputs`). In-process extensions are the powerful path: namespacing, declared permissions, per-skill tracking and atomic unload are an executable contract, not convention.

`skill_repair_admission.py` admits an ordinary managed repair against exact payload bytes (§6). The bucket/name short form still produces `skill_repair`, normalized to `normal` at promotion: a payload selector, not a reduced tool profile. Installed payloads need no Git copy; repair review never forces unload.

### Realtime providers

PluginAPI 2.1 `register_realtime_provider` (permission `realtime_provider`, in-process only) registers `<skill>:<name>` with `contracts/realtime.RealtimeRoute` (accounting provider/endpoint/model prefix). First consumer: `skills/openai_realtime/`. Providers own wire layout, acknowledgements and usage mapping; host content/fitting/authority/money stay shared, so another engine needs no core edit. `realtime_setup.py` retains imports through handler/socket teardown; unload removes dispatch and requests Stop. Reconcile requeues on release, preserving enablement. Local deletion removes the payload immediately, deferring state cleanup to import release and sparing a reinstall; process loss or cleanup failure can leave state retained.

`gateway/realtime.py` admits `chat.execution_transport` into ordinary room execution. `realtime_turn.py` previews complete prepared messages offline from cached route evidence. Funding checks capacity with the probe's actual output bound, without changing Nano's selected input; the physical attempt records bounded input for density learning. A setup-only consumer refuses an obligatory input-source substitution it cannot read. `realtime_execute` funds the exact wire digest once; usage stays reported or unknown. Handle/funding are process-local: recovery/Continue refuse replay, Pause refuses without a resumable checkpoint, Stop ends execution. This internal text probe is not Live Conversation. Wire details: `CLIENT_CONTRACT.md`.
