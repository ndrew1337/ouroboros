# 13. External Skills Layer

Discovery, review, grants, dependencies and enablement are separate: merging gates would turn a toggle into execution authority. Context snapshots: §6; author protocol: `CREATING_SKILLS.md`.

### Skill gates

Discovery grants no trust; PASS installs no dependencies; enabled does not mean ready. Install → preflight → digest-bound review/acceptance → grants → dependencies → enablement → execution; extensions also register (§10.8). Roots: §1. Enabled-peer conflicts apply symmetrically without deletion. `skill_lifecycle_queue.py` deduplicates mutations; panels lend the lane and persist only for installed bytes. Reviews stay private. UI calls dead/stale jobs interrupted without writes; list reads heal nothing. Lifecycle-locked ordinals follow job start, preserving retry history without making a UI counter authority.

Execution resolves the canonical directory through the full loader. Conflict reads use fresh manifest/enablement peers (`skill_peer_inventory.py`), not hashes or partial executables. Both use `skill_loader._native_platform_visible`: foreign built-ins stay hidden except re-seeded Unix remote on Windows (§2). Provenance survives OFF for intentional ON, without granting execution. `skill_conflicts.py` owns the shared verdict. Both refresh after slow lifecycle work: cross-process disable/revoke/restored-mtime edits apply next request; valid manifests retain conflicts even when payloads cannot be read.

### Skill review authority

Reviewer rights cover checks in a private copy, not activation; Full is not an OS sandbox. Preflight failure remains PENDING, never advisory-overridable BLOCKERS. `skill_identity.py` binds records to payload and dependency declarations, excluding install notes; conversion rebinds only unchanged bytes.

Host acceptance admits exact bytes via trusted source, Cyber-only `self_check`, owner Skip or selected-task owner edit. Owner-requested edits use `skill_owner_action` Skip with `owner_source`; edits stale acceptance. Review-source blockers remain off after Advisory author finish. Other authors may accept substantive feedback or an exact terminal job/hash with partial feedback or disclosed unavailability, running preflight and saving `author_disposition.review_reference`. A live silent critic is not unavailable. `SkillReviewState.gate_for` admits without rewriting critics: Blocking needs fresh approval; Cyber retains P0/P3 judgment. Publication: §6.

### Telegram built-in

`skills/telegram/` owns the in-process bridge and supervised companion: sidecar, tunnel/menu rollback, heartbeat, singleton. Text needs no tunnel. Grants are required; Colab waits for executable installation, auto-grants eligible items under the owner's choice, then enables. `state/skills/telegram/` holds binding, companion, rollback, cursors, tunnel cache and bounded derived message refs; map-write failures warn without stopping delivery.

Confined files enter `/chat/inject` → `data/uploads`; quiz answers use `/chat/decision`. Other replies carry row/work facts, never routing; notices reference work, not unseen Main answers. Earlier same-chat owner messages get native replies; Continue stays separate. Relays are silent on success, one line on failure. Oversized files link in-app or to an active Mini App, never starting a tunnel or publishing a URL. `lib/telegram_i18n.py` uses `OUROBOROS_UI_LANGUAGE` (§7), preserves host text; `/language` uses Host `/ui/language`. The completion toggle gates terminal/Main notices; Off consumes IDs. Replay enriches `completion_notice` (§3), not text. Silent Mode, replies/files/quizzes and salvage remain independent. Events only wake `TypingCue` over `gateway/reply_preparation.py` (DESIGN §9). `TELEGRAM_PROXY` covers Telegram API only. Locked dependency: `httpx[socks]`; limits/forms: the skill's `SKILL.md`.

`skill_catalogue.py` pages whole compact `list_skills` records, including disabled/unreviewed/broken/colliding entries and omission counts. Snapshots track membership, not atomic pages. Named reads return full diagnostics and `manifest.read` for the selected `SKILL.md`/`skill.json`; bodies stay in those files. Unreadable payloads do not hide readable manifests; unparsed/colliding manifests have no address. Unknown names return `found:false`; oversized details use the generic result source. `model_experience` reaches bounded context; `SkillManifestError.fix_hint` guides repair. Delegate index: §6.

### Sources, installs and dependencies

`skill_sources.py`: default Official trusted, Community review; trust edits affect future installs. HTTP shapes: `gateway/skill_source_contracts.py`.

Updates compare candidate and optional local digests: Replace keeps `.previous`, Keep skips, Merge uses the owner's task door. Review-basis updates retain payload/lifecycle state as `pending_update`. Completion, Skip and startup settle in the lane: accept executable bytes or restore/reconcile; review/preflight/landing/dependency failure records `update_rejected`. Startup leaves live reviews alone. Pre-update records restore interrupted landings; superseded installs discard snapshots. Partial restores retain evidence and never replace twice. No-review updates bind `owner_skip` to exact bytes. Starters accept any source: absent/blank means defaults, `[]` none; `OUROBOROS_STARTER_SKILLS_TURN_ON` defaults true (§7). Built-ins precede Git fetches.

ClawHub lands archives atomically with per-file hashes. Accepted dependency declarations authorize literal build/check argv (`marketplace/install_specs.py`); manual instructions remain guidance. `state/skills/<name>/dependency_cache` holds caches, `deps.json` results. Missing checks stay unknown; drift stales readiness. `provenance.py` clears only the local receipt. Script runtimes: `tools/skill_exec.py`, author protocol. Tool result composition and `PRODUCER_RESULT_SOURCE_JSON`/`FULL_RESULT_SOURCE_JSON`: `tools/tool_result.py`, `loop_tool_execution.py`.

### Extension import and isolation

`extension_import_staging.py` shares complete `__extension_imports/` trees by content and runtime/dependency identity. PID references survive until actual teardown. The cross-process imports lock lives beside disposable skill state, so deletion cannot replace its inode. Local delete removes payload and records the existing uninstall tombstone; live PID references defer state cleanup. Any same-name install, across sources, preserves shared state/grants. Cleanup errors retain the tombstone for normal sweep/release retry; completed import retirement does not strand reload admission.

Review/grants bind to code. Per-call children reuse the loader with scrubbed env and proxy tools/routes/WS/UI/settings/companion descriptors; persistent subscriptions/tasks need in-process or companion lifecycle. The capability matrix owns support, not platform names. `extension_catalog.json` caches success only for exhaustive `catalog_inputs`, hashing runtime, host revision, grants and declared settings/env, never storing values. Other dependencies retain the catalog child; bundled payloads never opt in implicitly. Namespacing, permissions, per-skill tracking and atomic unload bind the powerful in-process path.

`skill_repair_admission.py` admits ordinary managed repair against exact bytes (§6). Bucket/name still produces `skill_repair`, normalized to `normal` at promotion: a payload selector, not a reduced tool profile. Installed payloads need no Git copy; repair review never forces unload.

### Live Conversation and provider packages

PluginAPI 2.2's in-process `register_live_conversation` and `register_realtime_provider(..., session=...)` separate the feature (`skills/live_conversation/`: media/tools, Talk A) from `gemini_live`, `grok_realtime`, `openai_realtime` (wire, captions, usage, renewal). Routes bind accounting provider, endpoint and model prefix; no fallback. Beta defaults off regardless of keys.

`gateway/call_ws.py` admits an ordinary turn; `live_conversation.py` supplies its host port. Context, tool policy/executor/checkpoints, history, mailbox, model-wait Stop and attempt ledger keep their owners. `call_peers.py` carries provider audio directly; `call_protocol.py` preserves companion framing. Presence retains its ceiling, gate, registry and provenance: external audio cannot confer owner authority. Browser capture uses shared leases (§3).

The host seals/reserves connections before dispatch. OpenAI encodes the unchanged allowance as 1–4096 or `"inf"`; the latter needs fresh exact-route `response_limits` evidence for its model maximum. The physical request carries a known native bound even above the allowance. Unknown bounds (including Grok's absent limiter) remain `None`, with the ordinary allowance only an estimate. Receipts separate ordinary fit, allowance, evidence and reserve. Missing modality prices retain exposure; neither text prices nor text-density learning substitute for mixed usage. Gemini renews at a completed turn with full role history in system layout; host remeasures common context. Socket loss ends the call; no paid retry. Unload removes dispatch and requests Stop; imports outlive tool/history/socket teardown, then requeue reconcile.

`realtime_turn.py` separately previews whole input offline and funds one digest via `realtime_execute`. Its probe bound governs fit; required pointers need a reader. `realtime_setup.py` retains imports through close. Neither intent restores authority on recovery/Continue; Pause has no resumable checkpoint, Stop ends execution. Client shapes: `CLIENT_CONTRACT.md`.
