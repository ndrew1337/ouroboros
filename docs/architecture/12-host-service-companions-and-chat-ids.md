# 12. Host Service, Companion Processes, and Chat IDs

Connectors report supported events/facts; the host captures them before authored wakes and execution gates decide attention. Silent can wake; Paused admits no new focus. External speech retains provenance, never owner authority; unknown outcomes authorize no repeat.

### Host Service boundary

The Host Service (`ouroboros/gateway/host_service.py`, `OUROBOROS_HOST_SERVICE_PORT`) authenticates `x-skill-token` against payload hash, executable review, enablement and grants. Tokens hold no secrets, stale on edits and refuse stringification (`skill_token.py`); routes/permissions: §4. `POST /notify` (`host_notify.py`, `notify_owner` grant, `/identity.notify_version`) writes one sentence ≤`NOTIFY_TEXT_MAX_CHARS` as a `skill_notice` System row signed `Notice · <skill>` in the owner's chat, waking no model; 503 means unconfirmed. Review covers transport identity/attribution, bounded polling, panic cleanup, token confinement and exfiltration. Reviewed owner-bound transports may control Ouroboros; external slash commands use a separate positive-owner slot (`supervisor/state.py`): unidentified transports cannot bind, web identity cannot exclude the remote owner. `wait_for_response` is A2A-only.

Decision/language writers: §4. Review waits reach their live controller after author completion via `pending_action`; a stale revision/identity or absent consumer is 409 (§6 Quota and auth waits). A verdict grants no continuation or skill authority.

`host_service._RateLimiter` is a token bucket for `/ui/ws-message` bursts and sliding windows elsewhere. Refused relays aggregate per burst as `host_service_ws_relay_dropped` with count in `logs/events.jsonl`; child `send_ws_message` stays best-effort `None`, in-process broadcast unbounded.

`chat_uploads.store_upload` owns Host-confined paths/completed multipart spools, called directly by Host Service and through `gateway.files` for `/api/chat/upload`. The worker copies and closes its spool despite HTTP cancellation; skills keep sources. Neither ingress rejects size; `_INJECT_ATTACHMENT_MAX` and Files-upload policy remain separate. One request-local cleanup stack removes new unaccepted copies on partial copy/refusal/cancellation; replay adopts no duplicates. Accepted bytes survive disconnect/unknown outcomes, which claim no acceptance.

### Operation correlation

Named injection returns `operation_ref=<chat_id>:<client_message_id>` on 202/200/504/disconnect. `message_ingress.accept_local_message` accepts the name and raw `reply_to`; host resolution precedes the canonical row, which must land before enqueue. Same-id/text/skill replay rejoins even before dequeue; changed content/source/Reply yields 409. Content includes ordered attachment `[sha256,name]` (`chat_uploads.same_message`); regenerated storage names do not change identity.

Inline photos (`_INLINE_IMAGE_MAX` before decode; `CREATING_SKILLS.md` `inject_chat`) park once in `data/uploads` and always stage, retaining originals for model pixels. Non-image bytes stage as files, never vision under the transport's label. The queue is in memory: accepted delivery lost on crash reads `lost`, without second-enqueue authority. One same-id retry of a canonical write that raised in this process hands the row over as `queued`.

Routing annotations/outbound task ids only aid discovery. Reads/cancel require the queue/task's complete `origin_message_ref` to match the authenticated canonical skill source; `DirectActivityRegistry` carries that origin. Named waits poll that operation's retry-aware effective result; chat order proves no reply. Cancel enters durable intent/cascade custody (§5) only with matching origin and installation root; otherwise `cancel_unsupported` precedes writes. Unresolved custody never becomes false `cancelled`.

### Focus in places

`review_requested`/`assigned` are observed facts, never inferred words. Source-bound roots contact Main with `send_user_message(destination="main", request_id=...)` or `escalate(..., request_id=...)`. `presence_owner_contact.py` retains source facts for the voice line, preserving authored words. Messages use the outbox, questions `owner_quiz`, deferred events the attached supervisor bus. Identical retries rejoin; changed fields (waiting intent included) refuse. Only source-bound contact deduplicates omitted keys. Authority-only roots keep room questions; children report upward.

Live answers use the author's final-drain admission lock; late answers enter Main with the exact owner words, source snapshot and child reference. Only owner-started roots inherit `presence_binding_authority`, never an automatic external final; the owner stays unrestricted. Silent permits private contact; Paused preserves owed contact without new focus. Service/scheduled notices keep separate gates. Display routing: §3.

`/identity` independently advertises `presence_main_contact_version: 1`, `presence_work_output_version: 1` and `presence_wake_facts`; earlier place/continuation/delivery versions imply none. Missing required support is a setup gap, never fallback through owner ingress.

`POST /presence/turn` (`presence_runner.py`) admits exact provider/account/conversation/thread facts, skill-confined files and an authenticated place. Conversation and active-turn leases span processes; HTTP disconnect releases neither work nor capacity. Live retries join only matching conversation/actor/text under the turn ID; mismatch is `presence_event_identity_conflict` (409), never another room's answer. Refusals: CREATING_SKILLS "Places and focus transport ingress".

Unknown outcomes never authorize event replay. Before effects, the runner writes and reads its source-bound RUNNING row/controller; ambiguous writes allow receipt retry, not regeneration. Lost stacks, unknown terminals and cancellation return retained refusals: transports keep event/receipt, release input FIFO and observe original/child separately. `/presence/work` stays pending while the attempt can change (`presence_recovery.attempt_ended`), then serves canonical selected speech or failed/cancelled silent with unknown-effect facts. The orphan sweep records failed/`presence_attempt_lost`; `presence_recovery.py` keeps `host_task_facts` for room memory/consciousness without forced questions or apologies. Missing evidence proves neither silence nor no effect.

Only `presence_retry_proof` permits regeneration: first-round temporary refusal, every route engine-confirmed `not_started` and ledger-released, no response/tool/handoff, and a dated reset. After reset the conversation gate writes `presence_retry_next`, a new physical ID under the original event; other refusals stay retained. A live turn's shared fallback/continuation (§6) keeps earlier effects, unknown cost, controls and its conversation through recovery or retained refusal, never replaying the event.

`/presence/work` keeps queried `work_ref`, producer `task_id`, canonical `output_ref` and actual `child_work_ref` distinct. Consumers observe original, child and continuation outputs independently, including selected failed-terminal output, deduplicating by output identity, never text or polled work. Missing legacy identities stay missing (`test_presence_connector_contract.py`).

`presence_continuation.py` parks only for the author's left review (commit/change/result, `review_pause`) or required private Main question. It grants no generic sleep, detach, owner Pause or budget-pause callback. With tool, process and service custody idle, it records `open_turns` and a source-bound write-once initial envelope on the RUNNING task, reads them back, publishes the envelope, then lends conversation and active slot. Otherwise it waits holding custody. Reentry reacquires both in admission order before any model/tool/forced call and appends `[PRESENCE CONVERSATION RESUMED]` facts. Hard stops use the zero-call rail; rounds and wallet persist. Bound question waits resume without inventing consent; durable terminal rows reconcile questions and waits, including cancellations, while unknown attempts stay unconfirmed. Wait-ended events address the question's publication room.

Only `continuation_version: 1` consumers take the initial envelope; others await terminal. Reviews publish nothing themselves, released selections are never resent, and lost authors stay interrupted without automatic restart. An explicit new event can start a new author from retained facts. Wire: CREATING_SKILLS "Presence continuation".

Reentry keeps exact rows and gaps in immutable `presence_reentry` artifacts, read through existing task scope with `get_task_result(task_id, presence_reentry_sha256, …)` and `presence_reentry_offset`. It reads only the producer's conversation from `state/dialog.sqlite` within frozen bounds. Legacy cursors use the import ledger; new snapshots bind the end to a retained row identity. Inode/mtime-only snapshots report `legacy_source_identity_unavailable`, keeping their text; import gaps stay explicit (§6). `presence_observations.py` accepts transport-queue snapshots in `event.conversation.transport_queue` or authenticated work POSTs: dated observations, never inbox certainty, admission or delivery proof; absent means unknown.

Entry/receipt identity is `presence_bindings.conversation_key` (empty thread `0`). Durable `first_lent_at` anchors parks/termination; returning authors update their own `open_turns` entry without replacing newer pointers. Outcomes: `message`, `silent`, `tool_delivered`, `deferred` (requires admission; orphaned children replay silent). `peer_roster.independent_message_target` admits `forward_to_worker` to source-bound RUNNING turns as peer context, never owner authority. Proactive speech uses connector tools.

`places.py` owns atomic revisioned `state/places.json` for `ouroboros/gateway/places_api.py` and `configure_presence`. `place_projection.connect_declared_place` creates Silent in one write; repeat Connect keeps choices; low-level/migration defaults stay Active. Changed records take the next document revision; edit/disconnect compare the displayed revision, so stale writes are refused (current summary or null). Migration copies legacy bindings/instructions/topics/model/folder once, keeping files and route identities. Only owner doors/APIs confirm owner accounts; connector updates never replace saved choices.

`place_projection.place_view/places_view` owns PlaceSummary: label, sanitized icon, readiness, source/settings, facts, revision, rooms, nullable spend. Status and launch read the brief stored view; display money may be stale, admission strict. Connect reads account/conversation/label instances from the connector's source: absent, nonempty, empty and unavailable differ; null accounts never become wildcards; broad/narrow identities coexist. Wire: CLIENT_CONTRACT “Places”.

Contribution `facts` declares core kinds and labelled `signal.<slug>` kinds, `wakes` defaults; `/identity.presence_wake_signals: 1` advertises support. Intake, owner and tool signals need the connector's live declaration; saved choices stay removable while off. Logic/settings stay with connectors; core matches membership, never text, adds no Place field, keeps bot gating/OR semantics (CREATING_SKILLS).

`ouroboros/gateway/host_service_places.py` captures source events/attachments before admission. Paused, Off/Panic and unmatched events settle heard/silent; exhausted or unknown allowance requests retry. `conversation_lease.py` owns process/file locks, lending and reacquisition. Only an accepting local author with a held conversation lease receives `place_event` context-only mail, under its final-drain admission lock; a closed, ended or remote author leaves ordinary admission eligible. Accepted final-drain context earns a round, never owner authority. Stop finds remote lent authors by stack-lifetime locks; reentry checks `supervisor.consciousness_carriers.autonomous_work_enabled` before reacquiring, ending on the zero-call rail if disabled. Focus keeps consciousness provenance/autonomy and a root cost ceiling; no new capability ceiling, legacy ceilings stay decodable.

`presence_context.py` appends `prompts/FOCUS.md` after the shared prefix: actor/wake facts, authored notes, existing work, allowance, roots and folder address; full knowledge topics stay context. `finish_task` selects speech or silence. `place_reply.py` checks current Place state and Safety (`place_reply`) before automatic speech, including promoted roots with a retained destination but no wake stamp. Flags return to the mind; Silent/Paused/disconnected/Advises holds become one System row per task/reply subject. Forced finals cannot bypass an unresolved flag. Cached turns, continuation envelopes and polls recheck state without generation or another Safety call; outward silence keeps durable answer/output identity. Late receipts stay evidence with warnings. Existing transport custody and recovered-output identities persist.

Receipt mode is negotiated per turn (CREATING_SKILLS "Reporting actual Presence delivery"). `presence_delivery.py` accepts authenticated `/presence/delivery` observations through the chat writer: mode 1 logs outgoing speech on provider receipt, mode 0 logs delivery-unconfirmed authorship. Typed `presence_delivery` never finalizes a task; failures/uncertainty are System facts. Receipts prove writing, not reading. Identical readable reports deduplicate; conflicts refuse. Malformed retained rows yield `history_coverage=gapped`, where `duplicate=false` means only no readable match. Transport outboxes own reporting backoff; report failure neither resends nor blocks provider delivery. Deterministic client-id lookup in `state/dialog.sqlite` survives Host restart and refuses unknown import coverage.

### Live meeting peers

`presence_call.py` admits a connector's call by place, as `/presence/turn` does, and opens it only in an Active place whose current choices would start a focus for the event (wake match, consciousness on and not Advises, allowance left; the request is heard in the room first), under the same gate and `PROACTIVE_TURNS` registry with a loaded Live Conversation turn (§13). `/call/open` and `/call/{call_id}/peer` (`gateway/host_call.py`) require `call_peer`; new calls also require the connector's Presence grant. Attachment grants narrow mic/speaker/video directions and bind the token digest. The common peer parser preserves the meeting protocol; `presence_events.py` checks call origin identity. Final external captions remain Presence observations; playback evidence never makes a participant the owner. Meeting skills are unchanged.

### Companion processes

Reviewed manifest descriptors enter host-supervised durable custody, reconcile on lifecycle changes/restart, and stop on disable/unload/panic. `state/extension_generation.json` publishes the server's live set; workers adopt at task start/dispatch miss, so enablement is visible without pool respawn. Workers write durable `state/extension_reconcile/` requests instead of spawning server-owned children; reconcile names the answering process.

Aggregate/Skills health uses the server observation; worker health is only a qualifier, so failed handoff cannot advance `last_known_good`. Restart-budget exhaustion persists until successful start. Companion cwd is the reviewed payload: edits stale review before reload instead of silently changing a live process. Projection: `state/extension_companions.json`.

### Chat-id delivery

Each message has one destination; absence is `None` (§11.1 `chat_id_policy`). `HIDDEN_CHAT_ID=0` serves Skill Review/unbound headless work without a browser reader. `message_bus.notification_chat_route` chooses notices; history query chat 0 coerces to Main and excludes chat-0 rows. Lineage/admitted Project chat routes work to its Project; negative A2A ids never enter human streams.

An exhausted terminal outbox skips chat 0 while retaining incident/message. Only positive same-id/destination evidence suppresses notice (`terminal_delivery`), never bare ids or missing ACKs. Memory/consolidation use the same value/None policy: per-window registry snapshots name Main/Projects by stable ids; missing/ambiguous ids remain explicit, never default Main. Presence labels require transport facts re-deriving the chat id. Labels are read-only attribution, changing neither routing, visibility nor delivery.

`place_intake.py` decides attention; `place_arrivals.py` owns heard decisions, deferred sources and room/activity indexes. `loop_completion_schema.py` selects completion, preserving live legacy registries; `tool_effects.py`/`place_guard.py` own effects/targets (§13).

Heard-only events create no task/context blob; the room row keeps identity/reason (`paused`, `off`, `no_wake_match`, current-author handoff). Later On never reconsiders them. Focus/heard settlement share the intake lock and preserve custody. Source rows stay immutable; `dialogue_store` derives deferred pointers from dedup records; `chat_chain.source_row_id` preserves identity.

`places.place_room_index` reads latest arrivals and nonterminal focus counts through indexes, without historical walks or per-arrival document loads. Unknown task-store counts stay null. Only the owner's rooms endpoint requests arrival details, decoded after the transaction; polls stay index-only. Discovery may miss legacy/outgoing-only rooms; import/gap flags describe the store, not provider completeness. Indexes build once from source rows. `ouroboros/gateway/place_history.py` projects recorded delivery/heard facts, exact-task focus starts and current owner confirmation (CLIENT_CONTRACT “Places”). `account_candidates` suggests up to 20 nonbots from the newest 50 arrivals, without identity confirmation or another actor list. Migration imports valid neighbors, records bad bindings in `migration.problems` and publishes one marker; `/api/places` exposes `migration_problems`.

For an opaque outbox mutation (empty conversation id), `GET /presence/place` reports any Silent/Paused place owned by that authenticated connector/provider/account, including broad and migrated wildcard accounts. An optional `thread_id` resolves a topic-specific place; omission keeps the room lookup. Declared tool destinations match account, conversation and thread as separate facts, each recipient checked independently. Retained-work GET/POST may omit `binding_id`; authentication checks the retained task's connector, never the ref alone. POST accepts exactly `transport_queue` plus an optional `binding_id`; legacy binding ids remain checked.
