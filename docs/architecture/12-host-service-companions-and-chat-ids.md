# 12. Host Service, Companion Processes, and Chat IDs

Reviewed owner-bound transports are control surfaces. External speech remains attributed observation, never owner authority; unknown outcomes never authorize another attempt. Chat ids are values, including the hidden destination.

### Host Service boundary

`gateway/host_service.py` (`OUROBOROS_HOST_SERVICE_PORT`) authenticates every request with opaque `x-skill-token`, bound to payload hash, executable review, enablement and grants. Tokens contain no secrets, stale on edits and refuse stringification (`skill_token.py`). Routes/grants: §4. `POST /notify` (`host_notify.py`, `notify_owner`, `/identity.notify_version`) writes one sentence, at most `NOTIFY_TEXT_MAX_CHARS`, as a `skill_notice` System row signed `Notice · <skill>` in the owner's chat, waking no model; 503 means unconfirmed. Review covers identity/attribution, bounded polling, panic cleanup, token confinement and exfiltration. External slash commands require a separate positive-identity owner slot (`supervisor/state.py`): unidentified transports cannot bind; web identity cannot lock out the remote owner. `wait_for_response` is A2A-only.

Decision/language writers: §4. Review-operation waits reach their exact live controller after author completion via canonical `pending_action`; stale revision/identity or absent consumer yields 409 (§6 Quota and auth waits). Verdicts grant neither continuation nor skill authority.

One `_RateLimiter` has two policies: `/ui/ws-message` uses a token bucket, so a burst cannot silence a widget for the remaining minute; other lanes use a sliding window. Refused relays aggregate per burst into one durable `host_service_ws_relay_dropped` event with count in `logs/events.jsonl`. Child `send_ws_message` remains best-effort `None`; in-process broadcast is unbounded.

`chat_uploads.store_upload` owns both Host-confined files and completed multipart spools, called directly by Host and via `gateway.files` by `/api/chat/upload`. The request worker copies and closes its spool despite HTTP cancellation; skills retain sources. Neither ingress rejects by size; `_INJECT_ATTACHMENT_MAX` and Files-browser policy remain independent. Request-local cleanup removes only new unaccepted copies after partial copy/refusal/cancellation. Replay adopts no duplicates; accepted bytes survive disconnects and unknown write outcomes, which prove no acceptance.

### Operation correlation

Named injection returns `operation_ref=<chat_id>:<client_message_id>` on 202/200/504/disconnect. `message_ingress.accept_local_message` accepts the name and raw `reply_to`; host resolution precedes the canonical row, which must land before enqueue. Same-id/text/skill replay rejoins even before dequeue; changed content/source/Reply yields 409. Content includes ordered attachment `[sha256,name]` (`chat_uploads.same_message`); regenerated storage names do not change identity.

Inline photos (`_INLINE_IMAGE_MAX` before decode; `CREATING_SKILLS.md` `inject_chat`) park once in `data/uploads` and always stage, retaining originals for model pixels. Non-image bytes stage as files, never vision under the transport's label. The queue is in memory: accepted delivery lost on crash reads `lost`, without second-enqueue authority. One same-id retry of a canonical write that raised in this process hands the row over as `queued`.

Routing annotations/outbound task ids only aid discovery. Reads/cancel require the queue/task's complete `origin_message_ref` to match the authenticated canonical skill source; `DirectActivityRegistry` carries that origin. Named waits poll that operation's retry-aware effective result; chat order proves no reply. Cancel enters durable intent/cascade custody (§5) only with matching origin and installation root; otherwise `cancel_unsupported` precedes writes. Unresolved custody never becomes false `cancelled`.

### Focus in places

`POST /presence/turn` (`presence_runner.py`) admits exact provider/account/conversation/thread facts, confined files and an authenticated place. Conversation/active-turn gates hold cross-process leases; HTTP disconnect neither cancels nor releases capacity early. Only a continuing author's yield lends capacity. Live retries join by turn ID only when canonical conversation, actor and text match; otherwise 409 `presence_event_identity_conflict`, never another room's answer. Wire dispositions: CREATING_SKILLS “Places and focus transport ingress”.

Unknown outcomes never execute twice. Before effects, `handle_task` writes and reads back a source-bound RUNNING row naming its controller. Ambiguous writes remain retryable without regeneration authority. Lost stack, unknown terminal or cancellation retains a refusal: transport keeps event/receipt, releases its input FIFO, and observes original and actual child separately. `/presence/work` stays `pending` while the attempt can change (`presence_recovery.attempt_ended`), then returns canonical answer or `failed`/`cancelled` with `outcome:silent` (nothing more to deliver) and unknown facts. Released outputs retain identities; orphan sweep records `failed`/`presence_attempt_lost`. `presence_recovery.py` retains `host_task_facts` for room memory and ordinary consciousness, forcing neither owner question nor correspondent apology. Missing evidence proves neither silence nor absence of effects.

Only `presence_retry_proof` permits regeneration after quota refusal: first-round temporary refusal, every route engine-confirmed `not_started` and ledger-released, no response/tool/handoff, dated reset. After reset the conversation gate writes `presence_retry_next`, a new physical ID addressed by the original event. Other refusals remain retained. Pure-model recovery in a running turn uses shared configured fallback/continuation (§6), preserving tools and unknown cost. The turn keeps conversation controls until recovery ends or retains refusal; it never replays the event.

`presence_continuation.py`: an author awaiting an addressed review (`review_pause`: commit/change/result) retains stack/task/controls/paid review while lending its conversation. At the review park, only when its tool/process/service custody is idle, it writes and reads back a source-bound, write-once initial envelope on RUNNING, registers in `open_turns`, publishes, then lends conversation and active slot. Before another model/tool/forced call it reacquires both in admission order and reads `[PRESENCE CONVERSATION RESUMED]` facts since yield. Hard Stop takes the zero-call rail; rounds/wallet never reset.

Only `continuation_version:1` consumers take initial envelopes; verdicts publish nothing. Released `output_ref` never resends; consumers without continuation support wait for terminal. After the attempt ends, later turns see `interrupted`; no automatic author restart occurs. An explicit new event continues retained facts as a new turn. Wire: `CREATING_SKILLS.md` “Presence continuation”.

Reentry preserves exact rows/gaps in immutable `presence_reentry` in the existing task artifact store. Existing task-read scope reads `get_task_result(task_id,presence_reentry_sha256,…)`, paged by `presence_reentry_offset`; reentry adds no reader/capability. Reads probe the producer's conversation chat in `state/dialog.sqlite` within frozen byte bounds. Legacy cursors use the import ledger; new snapshots bind their end to a retained row identity. Inode/mtime-only pre-cutover snapshots report `legacy_source_identity_unavailable`, retaining readable text. Import gaps never mean empty-complete (§6). `presence_observations.py` records dated transport queue observations (`event.conversation.transport_queue` or authenticated `POST /presence/work/{continuation_ref}`), never inbox certainty, admission or delivery proof; no snapshot means unknown.

Entry and receipts key on `presence_bindings.conversation_key` (empty thread `0`). The durable `first_lent_at` anchors later parks and terminal writes, so a returning author updates its own open entry without replacing a newer turn's pointer; `open_turns` retains each unfinished author independently. Outcomes are `message`, `silent`, `tool_delivered` and `deferred`; deferred requires admission, and orphaned children replay silent. `peer_roster.independent_message_target` admits `forward_to_worker` to a source-bound RUNNING turn as peer context, not an owner directive. Proactive speech uses connector tools.

`places.py` owns the revisioned, atomically edited `state/places.json`. A one-time migration copies legacy bindings and behavior instructions, topics, model and folder without deleting source files or changing origin/destination identity. `ouroboros/gateway/places_api.py` and `configure_presence` share its writer; only an owner-door turn or authenticated owner API can confirm an owner account. A connector update cannot overwrite owner or mind choices.

`ouroboros/gateway/host_service_places.py` captures each source event and attachments before wake, allowance or capacity decisions. Paused, Off/Panic and unmatched events settle as heard/silent without model work. Exhausted or unknown allowance asks the transport to retry. `conversation_lease.py` owns the existing process and file locks, lending and reacquisition; a live author receives `place_event` context-only mail only while its intake is accepting under the same local admission lock used by its final drain and a held conversation lease. A closed, ended or remote author leaves ordinary focus admission eligible; a final drain that accepted new place context gives that author a round to consider it without changing owner authority. Stop sees lent authors in other processes through their held stack-lifetime locks too. Reentry checks `supervisor.consciousness_carriers.autonomous_work_enabled` before reacquiring and uses the ordinary zero-call control rail when disabled. The focus has consciousness provenance, autonomy and a root cost ceiling, with no new capability ceiling; old stored ceilings remain decodable.

`presence_context.py` places `prompts/FOCUS.md` at the user tail after the shared prefix, with host actor facts, matched authored wakes, authored notes, existing work, allowance, roots and the folder address. Full knowledge topics remain context. `finish_task` selects an answer or silence. `place_reply.py` checks current place state and calls Safety with `place_reply` before automatic speech: flags return to the mind, Silent/Paused/disconnected and Advises holds become System rows, and late delivery receipts remain evidence with a visible warning. The retained place/destination carrier selects this boundary for promoted roots too, without a wake stamp. Cached turns, continuation envelopes and work polls recheck current place state without generation or another Safety check; silence is an outward projection that preserves the durable answer and output identity. One notice per task and reply subject records a hold. A forced final that cannot return a flag to the mind is held. Transport custody, receipts, continued outputs and recovered work keep their existing identities.

Per-turn receipt negotiation: `CREATING_SKILLS.md` “Reporting actual Presence delivery”. `presence_delivery.py` accepts authenticated `POST /presence/delivery` through the chat writer. Mode 1 writes outgoing history on provider receipts; mode 0 keeps authored, delivery-unconfirmed rows. Typed `presence_delivery` speech never finalizes tasks; failed/uncertain attempts are System facts. Receipts prove writing, not reading: identical readable reports deduplicate, conflicts refuse. Malformed retained rows yield `history_coverage=gapped`; there `duplicate=false` means only no indexed readable match. Transport outboxes own receipts/report backoff; slow/failed reports neither resend nor block delivery. Deterministic client-id lookup in `state/dialog.sqlite` survives Host restart and refuses unknown import coverage.

### Live meeting peers

`presence_call.py` admits a connector's call by place, as `/presence/turn` does, and opens it only in an Active place whose current choices would start a focus for the event (wake match, consciousness on and not Advises, allowance left; the request is heard in the room first), under the same gate and `PROACTIVE_TURNS` registry with a loaded Live Conversation turn (§13). `/call/open` and `/call/{call_id}/peer` (`gateway/host_call.py`) require `call_peer`; new calls also require the connector's Presence grant. Attachment grants narrow mic/speaker/video directions and bind the token digest. The common peer parser preserves the meeting protocol; `presence_events.py` checks call origin identity. Final external captions remain Presence observations; playback evidence never makes a participant the owner. Meeting skills are unchanged.

### Companion processes

Reviewed manifest descriptors enter host-supervised durable custody, reconcile on lifecycle changes/restart, and stop on disable/unload/panic. `state/extension_generation.json` publishes the server's live set; workers adopt at task start/dispatch miss, so enablement is visible without pool respawn. Workers write durable `state/extension_reconcile/` requests instead of spawning server-owned children; reconcile names the answering process.

Aggregate/Skills health uses the server observation; worker health is only a qualifier, so failed handoff cannot advance `last_known_good`. Restart-budget exhaustion persists until successful start. Companion cwd is the reviewed payload: edits stale review before reload instead of silently changing a live process. Projection: `state/extension_companions.json`.

### Chat-id delivery

Each message has one destination; absence is `None` (§11.1 `chat_id_policy`). `HIDDEN_CHAT_ID=0` serves Skill Review/unbound headless work without a browser reader. `message_bus.notification_chat_route` chooses notices; history query chat 0 coerces to Main and excludes chat-0 rows. Lineage/admitted Project chat routes work to its Project; negative A2A ids never enter human streams.

An exhausted terminal outbox skips chat 0 while retaining incident/message. Only positive same-id/destination evidence suppresses notice (`terminal_delivery`), never bare ids or missing ACKs. Memory/consolidation use the same value/None policy: per-window registry snapshots name Main/Projects by stable ids; missing/ambiguous ids remain explicit, never default Main. Presence labels require transport facts re-deriving the chat id. Labels are read-only attribution, changing neither routing, visibility nor delivery.

The place implementation is split by responsibility: `places_migration.py` reads legacy inputs once; `place_intake.py` decides attention after capture; `place_arrivals.py` stores heard-only decisions in existing room dedup records, defers source blobs until focus admission, and reads room/activity indexes; `place_projection.py` builds owner summaries; `ouroboros/gateway/places_api.py` writes owner choices; `ouroboros/gateway/host_service_places.py` serves connector intake, lookup and receipts. `loop_completion_schema.py` selects the available completion entry, preserving an already-live legacy registry. The declared-effect and target checks come from `tool_effects.py` and `place_guard.py` (§13).

Heard-only events leave no task document or context-source blob. Their existing accepted room row retains the event identity and a final attention reason (`paused`, `off`, `no_wake_match`, or current-author handoff); a later On does not reconsider a retry. Focus start and heard settlement share the intake lock, so an admitted task keeps its original custody. The immutable source row is never rewritten; `dialogue_store` projects the deferred focus-source pointer from its existing dedup record; `chat_chain.source_row_id` keeps the original source identity for that typed reader projection.

The Places view uses indexed newest-arrival seeks and a SQL aggregate of nonterminal focus facts, with no historical arrival walk or per-arrival document load. `places.place_room_index` returns captured room addresses and nullable unanswered counts; absent task-store knowledge stays unknown. The SQLite indexes build once and remain derived from their original rows. `account_candidates` suggests at most 20 people from the newest 50 indexed arrivals, omitting bots; these suggestions neither confirm identity nor retain a second actor list. Partial legacy migration records each bad binding in `migration.problems`, imports valid neighbors, and publishes the marker once. `GET /api/places` exposes `migration_problems`.

For an opaque outbox mutation (empty conversation id), `GET /presence/place` reports any Silent/Paused place owned by that authenticated connector/provider/account, including broad and migrated wildcard accounts. An optional `thread_id` resolves a topic-specific place; omission keeps the room lookup. Declared tool destinations match account, conversation and thread as separate facts, and each recipient is checked independently. Retained-work GET/POST may omit `binding_id`; authentication checks the retained task's connector, never the ref alone. POST accepts exactly `transport_queue` plus an optional `binding_id`; legacy binding ids remain checked.
