# 9. Shutdown & Process Cleanup

Close keeps the daemon; Restart stops work before transfer. Signals, timeouts and engine terminal facts prove no OS exit. Jobs stay until return; cold receipts grant custody, not Resume (§6). Switching restores stopped handles; boot retries unconfirmed custody.

### Shutdown doors

| Door | Stops | Keeps | Durable mark |
|---|---|---|---|
| Window close with keep-running on (desktop, live indicator) | nothing: the window hides | every task, schedule, companion and the daemon | none |
| Close, quit, SIGTERM, launcher gone (pipe EOF, POSIX too) | this generation's workers, services and owned executor/task processes, unfinished reviews included | the shared daemon and its clients; saved pauses; saved work, held for Resume | `server_shutdown.cause`: `external_signal`, `launcher_quit` or `launcher_gone` |
| Planned restart (self-restart, update, rollback) | the same; an off-pin daemon unless newer | saved pauses; saved work and the runnable queue, returned; a same-pin or newer daemon | the restart handoff |
| Manual Restart (owner) | the same plus the installation daemon and every delegated run it serves, other clients' included | saved pauses; saved work and the runnable queue, returned | restart transaction `door=owner_restart` |
| Panic | all owned work | sleeping work: owner Resume; working: saved for Resume after launch; existing pauses unchanged | `panic_stop.flag` (`panic`), then `panic_ingress_receipt` |

**Desktop.** `launcher_background.py` hides keep-running close only behind a live indicator; unset choice asks/saves once. Quit asks nothing, neither cancels nor sets Panic. Both latch startup/handoff shut. Early Quit closes setup windows, stops captured/bootstrap children and identity-proven servers, sparing stale companions. Tray/window Panic stops captured/bootstrap children; non-daemon `execute_panic_stop` persists/exits. Windows owns Popen until transfer; Panic never waits. New source checks inherited parent exit; old source/failed inheritance leaves late spawn unproved. POSIX captures descendants before orphaning; timeouts give no total bound. Windows keeps Job-error fallback. No HTTP/callback/replay; failures disclosed. Android loopback uses `/api/command /panic`; second launch opens during boot; Linux closes normally.

Close releases the PID lock; the daemon outlives windows outside the Windows launcher Job (custody: §1). `launcher.stop_agent` sends `quit\n` over private stdin (`OUROBOROS_LAUNCHER_STOP_STDIN`, all platforms; else SIGTERM), waits `LAUNCHER_STOP_GRACE_SEC`, then forces group/Job cleanup, keeping handle/record until confirmed exit. Quit/EOF/signals latch stop immediately. `SERVER_GRACEFUL_SHUTDOWN_TIMEOUT_SEC` bounds Uvicorn drain; a backstop exits after launcher grace. Custody completes even on group signals. `_exit_signalled` stays set, preventing settings saves from reviving the supervisor; fresh lifespans clear `_supervisor_stop` (`server.py`).

### Restart and retention

Teardown marks the generation, bounded-joins the supervisor and stops workers before optional waits; the watcher owns handoff. `owned_shutdown.stop_owned_work` shares first-door grace (§10 invariant 6), including event-log locks, retains `unconfirmed_since` and retries custody before admission. Pin changes use `server_restart._stop_owned_daemon_for_new_pin`; after stop evidence, `store_switch.switch_at_restart` exports/retires storage and moves the checkout, retaining uncertain intent for boot recovery. Return needs launcher exit 42 or a locked one-shot successor: same-PID exec, custodied POSIX spawn, or Windows original-parent HANDLE exit 42 with measured births. Only that successor returns work/queue; undispatched wait/planned carriers retain transaction gates. Failed binding holds work; Panic stays available. Re-upgrade with unconsumed Windows handles is unqualified. Listeners end with the server; companions use PID/reserved-port custody (§12), never port sweeps.

Manual Restart (`server_restart._perform_owner_restart`) refuses conflicts or an unwritable transaction before teardown. It writes `door=owner_restart`, `status=prepared`, generation/PID; live server latches and same-generation workers stop starts, never as Panic. `prepare_restart_returns` adds named returns; boot consumes only a prior generation's door after holds and `record_restart`, setting `door_applied_at` independently of ACK. Legacy Restart flags/bytes translate once as this boot's door. Teardown retains saves, reads attach-only custody, never ensures a dead daemon. Unconfirmed cleanup remains visible, not a Restart veto. A 404 proves absence, not output/spend; store-bound runs need the same store.

**Retention.** `restart_retention.py` keeps pauses, revokes unused grants and yields spent carriers to newer continuation custody. Warm owner Pause converts to cold; acknowledged planned/update sleep returns, manual Restart holds it. Doors replace only `saved_sleep_recovery` and `continuation_writer_unsettled`; stronger prior stops survive, even Panic. Panic gives sleeping work `panic_hold`/owner, working work `saved_work_hold{door:panic}`/resume; stored release never changes retrospectively. Source/money/time/Stop still govern; unknown dispatch is not unstarted. Cold receipts bind custody, not external survival. Resume removes the stop; history stays in the journal. Rollback loses Q9 checks; old launchers may require the removed Restart flag (PERSISTENCE).

### Panic path

Panic latches at ingress; thread-start failure runs synchronously. Owned stops (restart successor too) precede bounded persistence and installation census, daemon or not. The executing process, parent and pid 1 are spared. Census follows observed Panic exit or local tray/window Panic; the indicator leaves without waiting. Boot retries only saved pid/birth pairs in `state/panic_sweep_pending.json`; a flag grants no new discovery. Settlement misses undiscovered work; stopping old controllers may affect new attachments. Diagnostic faults spare other stop owners; failed writes cannot prevent exit 99, which authorizes no successor. Worker socket grace, lifelines and parent kills have separate bounds. Requests prove no exit; inaccessible/unpublished/backend-only children remain unconfirmed. WS/HTTP uses `LocalChatBridge.panic` without supervisor I/O; Host Service authenticates skill and pinned owner (§12). Only installation gates read `installation_stop.py`: Panic bytes and file identity. Boot persists work stops and disabled controls, then `state.json.panic_ingress_receipt`, then unlinks. Failed unlink repeats only deletion; new identity reapplies Panic; failed controls keep it closed.

Browser Panic sends once on its captured open socket with no buffered output; `panic_accepted` means latch, not exit. No confirmation, upload/save wait, replay or clock check; sent bytes may arrive late. `panic_source.py` journals causal ids and guards newer snapshots from late enrichment. Unknown PIDs stay unknown; diagnostics neither authorize nor veto.

Local tray/window Panic bypasses the observed-99 `kill_runtime_orphans` finalizer, which signals saved companion PIDs/ports without fresh identity proof. Escaped companions with unreadable/absent scope markers remain unconfirmed by captured trees and census (§12).

### Owned daemon stop and startup failure

`OwnedClaudexorDaemon.stop_outcome` reports `stopped`, `nothing_to_stop` or `unconfirmed`. With an owned marker and authenticated same-home endpoint, `daemon stop --json` needs exit 0 and a terminal receipt, not RPC/lease acknowledgement. Forced signals use only pre-request birth/command identities or the manager's Popen; confirmed death alone retires custody (DEVELOPMENT "Process Custody Rule"). Lock/RPC/exit waits have separate bounds, no promised total. Beyond `CLAUDEXOR_STARTUP_WAIT_SEC`, a live child stays `daemon_starting`; a silent listener is `daemon_not_answering`, an exited child `daemon_spawn_failed`.

**Startup failure.** `claudexor_startup_failure.py` labels the child's `daemon.log` interval `heap_exhausted`, `writer_lease_contended`, `engine_floor` or `unclassified`, carried by `daemon_spawn_failed`, `last_error` and one `claudexor_daemon_start_failed` row. Only `ExitFact.failed_without_control` latches spawning. Live attach or a new manager clears its latch; the server's also clears on the custody sweep (§5), with one zero-wait ensure after release, or owner Refresh (`/api/claudexor/wake`, one spawn per press); workers need attach or respawn. Releases record `claudexor_daemon_start_latch_cleared` and `cleared_by`. Probe `launch.nodeArgs` supplies `--max-old-space-size`; explicit `NODE_OPTIONS` wins; absent or malformed data keeps the plain command (`runtime_launch_invalid`). Residuals: `ExitFact`, `OwnedClaudexorDaemon.clear_start_failure_latch`.

`claudexor_exit_facts.py` reads a bounded `supervisor.jsonl` tail for context (saved exits use observation time, not death time; context never calls the engine). The authenticated `/api/claudexor/status` read adds live `memory`, `loop`, `store`, `servingMode`, effective `capacity` and class `admission` (nulls for absent measurements; finite, unlimited and unknown caps stay distinct); one dated `claudexor_engine_capacity` snapshot per descriptor generation survives beside fresh observations and independent stale facets in Settings → Accounts (§3); no measurement grants lifecycle authority.

Claudexor 4 first-start import can keep an authenticated daemon in `recovery_only` for minutes: `ensure_owned_gateway` waits `CLAUDEXOR_ADMISSION_WAIT_SEC`, then refuses typed `daemon_recovery_only` without killing it; passive status still shows migration progress. Engine storage, forward-only compatibility and logical/physical quarantine: PERSISTENCE.md. External-host CLI/MCP bindings only attach; this manager keeps start/stop ownership; standalone installations keep their own.

### Process custody

`_active_subprocesses`, task-attributed executor records (§1) and ledgered task processes are named by `state/owned_processes.json` (contended registrations land in `owned_processes.pending/`), read by exit and Panic instead of walking `data/state`; the boot coordinator indexes older records once. Groups and Jobs miss escaped descendants, so signals need measured identity; startup recovery settles no executor backend, retrying only stamped stops. Docker CLI exit proves no backend exit: `backend_completed` persists before marker deletion; a lost reply retains evidence, never signalling a completed CLI PID. `docker_process_observer.py` reads container `/proc`: a zombie leader is exited (return code unknown), stops and writer fences need no live group member, unreadable stat stays unknown custody. Host unwind or exact worker death retires the local invocation only (§6); unknown effects never authorize replay.

Only a measured birth/command mismatch retires stale owned-process custody, recorded first as `process_not_ours` in `supervisor.jsonl` with both fingerprints (`process_custody.record_not_ours`; the reaper and update quiescence record the same refutation before pruning); a foreign leader's EPERM, a reused non-leader, unreadable identity or a failed signal proves nothing and keeps the stop, never ages it out. Panic's independent scope census and exit verification remain.

**Work scopes** (`process_scope.py`). Plant an installation marker before spawning; daemon, kept services, MCP and extension children/companions keep it, shedding task markers. Invocation identity—not display labels—binds commands, task skills and non-kept services to markers/groups. Only truly-terminal transitions end leftovers by measured birth, never Pause/hold/handoff/placeholders. Retire after recorded settlement (denied signals are final) or `unsupported`; unknown identities stay owed. Panic reads the owned engine's schema-1 `daemon/run-scopes.json`; full settlement needs an absent/valid index. Limits: recycled leaderless groups may pass reuse checks, Linux nondumpable/setuid peers and macOS system binaries may hide markers, shell exit can leave children uncaptured; command-launched GUI children have no lifetime exemption; Windows/Docker-executor children stay `unsupported`.

**Follow-up controls** (§5). Recorded cancel intent wins over the door's cause (`followup_policy`); failed Stop transfer retains it. Unreadable stores invent no control. Restart records its episode; Panic needs no schedule control.
